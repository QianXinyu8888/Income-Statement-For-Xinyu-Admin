# 交易明细直接序号排序设计

## 目标

删除飞书「闲鱼交易明细」表中的“排序”字段，并让 Web 端以飞书接口返回的当前行顺序作为唯一的来源顺序。Web 默认倒序展示：飞书最后一条记录显示在 Web 第一条，且不保存、不展示额外序号字段。

## 已确认口径

- “直接序号”指飞书表当前从上到下的行位置，而不是单独维护的业务字段。
- Web 默认反向展示该顺序；筛选后仍保持来源记录之间的相对倒序。
- 分析页跳转定位先按同一来源顺序计算分页，再滚动并高亮目标订单 1.5 秒。
- 商品名称等现有可排序列仍可临时排序；重置筛选后恢复来源顺序倒序。
- 新增、编辑、导出和 API 响应均不再包含“排序”字段。

## 技术方案

交易列表查询增加内部排序模式 `sourceOrder`。它不是飞书字段：升序直接保留 `listRecords` 返回顺序，倒序复制并反转筛选结果。其他字段仍沿用现有比较排序。

领域模型移除 `sortOrder`；飞书记录映射不再读取“排序”，写入时也不发送该字段。编辑抽屉、CSV/Excel 导出、API 查询白名单和相关测试同步移除该字段。

代码兼容并通过测试后，使用飞书 Base 字段删除命令删除已确认的字段 `fldnnHnDwn`，随后重新读取字段列表，确认“排序”字段已不存在。现有记录不需要迁移，因为顺序来自记录列表本身。

## 边界行为

- 筛选结果为空时返回空列表。
- 反转时不修改 `listRecords` 的原始数组。
- `focusId` 不存在时继续使用请求页码；存在时按来源倒序后的索引计算页码。
- 飞书行顺序后续发生变化时，Web 下一次重新请求会自然使用新顺序。

## 验证

- 领域测试验证来源升序、来源倒序、不修改输入、筛选后的相对顺序与聚焦分页。
- 页面测试验证首次加载和重置均请求 `sourceOrder + desc`。
- 映射、抽屉和导出测试验证应用不再读写或展示“排序”。
- 运行全部测试、类型检查、lint、格式检查和生产构建。
- 通过本地页面确认默认顺序、分析定位与 1.5 秒高亮无回归。
