# 交易明细飞书顺序同步设计

## 目标

使 Web 端“交易明细”的默认记录顺序与飞书多维表格“闲鱼交易明细”当前网格视图保持一致，同时保留用户在 Web 端临时点击其他列排序的能力。

## 已确认的飞书配置

通过飞书多维表格读取到以下真实配置：

- Base：闲鱼交易明细及损益表
- 数据表：闲鱼交易明细
- 网格视图：表格
- 当前排序字段：排序
- 当前排序方向：升序

因此，本次同步的确定性规则是按交易记录的 `sortOrder` 从小到大排列，而不是依赖飞书记录接口未指定视图时的返回顺序。

## 默认与交互行为

- 交易页首次打开时使用 `sort: 'sortOrder'` 和 `order: 'asc'`。
- 搜索、状态筛选、日期筛选和分页均在该默认排序结果上执行。
- 从分析页定位产品时，服务端先按“排序”字段升序排列，再计算目标订单所在页；自动滚动和 1.5 秒高亮行为不变。
- 用户点击现有可排序列时，可临时改用该列排序；再次点击同一列继续切换升序和倒序。
- 点击“重置筛选”后恢复 `sortOrder + asc`，而不是恢复售出日期倒序。
- 不在交易明细中增加“排序”展示列，也不改变用户已确认的 11 个业务字段顺序。

## 空值规则

有“排序”值的记录按数值升序排列。`sortOrder` 为空的记录统一排在有值记录之后；多条空值记录保持飞书接口返回时的相对顺序。

该空值规则只适用于默认的“排序”字段排序。用户临时切换其他字段时，继续使用现有字段排序逻辑。

## 数据与组件边界

- `TransactionsPage` 负责初始化和重置默认查询参数。
- `queryTransactions` 负责默认排序中的空值置后，并继续在排序后计算定位订单的分页。
- API 查询 schema 和客户端查询类型已经支持 `sortOrder`，无需修改飞书字段映射、接口结构或环境变量。
- 不动态读取飞书视图配置，不增加额外的飞书请求；如果以后飞书视图改用其他排序规则，需要同步调整 Web 默认值。

## 错误与兼容处理

- 所有记录的“排序”字段都为空时，保留飞书接口返回顺序。
- 相同“排序”值依赖稳定排序，保持输入记录的相对顺序。
- 现有列头排序、筛选、分页、导出、编辑、批量操作和分析页跳转逻辑保持可用。

## 测试与验证

- 页面测试验证首次请求使用 `sortOrder + asc`。
- 页面测试验证重置筛选恢复 `sortOrder + asc`。
- 领域测试验证数值升序、空值置后、相同值与全空值保持相对顺序。
- 领域测试验证定位订单仍能在默认飞书顺序下计算正确页码。
- 完整运行单元测试、类型检查、lint、格式检查和生产构建。
