# 闲鱼损益后台 Codex 风格 UI 全面优化设计

## 目标与范围

在不改变现有业务能力、API、数据字段和路由的前提下，全面优化登录、交易明细、经营概览、利润分析、设置、交易抽屉、确认弹窗、加载/错误/空状态，以及桌面端、移动端、浅色和深色主题。允许重组信息层级，但不得新增虚构指标、无后端支持的筛选器或额外导航。

视觉目标是 Codex 式专业工具极简：冷静、克制、清晰、高效。层次主要来自排版、留白、细边框和状态变化，而不是大面积阴影、渐变或装饰。圆角采用中等尺度，不做硬直角，也不做柔软胶囊化。

## 设计系统

### 色彩

浅色主题：

- 页面背景：`#f7f8fa`
- 主表面：`#ffffff`
- 次表面：`#f2f4f7`
- 主文字：`#17191c`
- 次文字：`#6f7680`
- 边框：`#e1e5ea`
- 强边框：`#cfd5dc`
- 交互强调：低饱和蓝灰，焦点与选中态允许使用克制蓝色
- 利润/成功：`#169b55`
- 亏损/危险：`#df3138`
- 警告：琥珀色图标与极浅背景，不使用大面积黄色

深色主题：

- 页面背景：`#0f1012`
- 导航/顶栏：`#121316`
- 主表面：`#17191d`
- 次表面：`#1d2025`
- 主文字：`#f1f3f5`
- 次文字：`#9ba1aa`
- 边框：`#2a2d33`
- 选中态：`#1d2633`
- 语义绿红提高亮度以满足对比度，不使用霓虹效果

### 字体与字号

字体栈使用 `Inter, ui-sans-serif, -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。中文依赖系统优质无衬线字体，不引入阻塞加载的远程字体。

- 桌面页面标题：28px / 700 / 1.2 / `-0.035em`
- 移动页面标题：24px / 700 / 1.25 / `-0.025em`
- 页面说明与正文：14px / 400 / 1.55
- 模块标题：17px / 650 / 1.3
- 抽屉标题：20px / 700
- 核心金额：26–30px / 600 / 1.1
- 移动核心利润：28px / 600
- 桌面表格、按钮、输入框：13px / 500
- 移动按钮和输入框：14px / 500，触控高度至少 44px
- 表头、字段标签、图表轴：12px / 500
- 辅助与错误文字：12px / 400 / 1.45

金额、日期、百分比、数量统一启用 `font-variant-numeric: tabular-nums`。控件字号必须显式定义，不依赖浏览器默认值。

### 几何、边框与阴影

- 按钮、输入框、筛选器、导航选中项：8–10px
- 表格、图表、摘要带、移动列表容器：12px
- 抽屉左侧或移动底部表单顶部：12px
- 确认弹窗：12px
- 状态标签保持紧凑，允许 5–6px 小圆角，但不使用全胶囊形
- 边框以 1px 为主；仅浮层使用低强度双层阴影
- 页面不使用渐变、玻璃拟态、光晕或装饰性大卡片

### 图标

继续使用 Lucide，统一 1.75px 视觉线宽。桌面导航 18px、移动导航 20px、按钮内图标 15–17px。图标与文字基线对齐；选中状态通过文字颜色、浅背景和左侧细指示条表达，不更换图标隐喻。

## 页面结构

### 应用壳

桌面使用约 176px 的窄侧栏，显示图标与页面名称；顶部保留安静的工具栏，显示主题、账号与退出，不添加搜索或通知。主内容区最大宽度约 1440px，宽屏保持稳定内边距。

移动端隐藏桌面侧栏与顶栏，使用固定四项底部导航，包含安全区内边距。页面内容为底部导航预留空间。

### 交易明细

桌面顺序：标题与本月利润、主操作、统一搜索/筛选/导出工具栏、表格、分页。表格继续保留现有全部字段与排序；选中后显示贴近底部的批量操作条。桌面不把交易行改成卡片。

移动端使用开放列表，每行展示商品、状态、购入/售出日期、购入成本/总成本、利润等主要信息。列表通过细分隔线区分，不使用卡片堆叠。筛选继续使用可展开面板；选中后批量操作条位于底部导航之上。

### 经营概览

桌面使用一条五列经营摘要带，利润使用语义绿强调。数据质量提示位于摘要与图表之间。月度利润是主视觉，并完整展示正负基线。

移动端先突出利润，再以 2×2 账本式布局展示销售额、总成本、ROI、成交笔数；图表区域允许横向滚动，避免将 21 个月挤到不可读。

### 利润分析

桌面顶部保留日期范围；月度利润趋势占据主区域；下方三列分别是利润区间、状态分布和退货摘要。列表只展示现有 API 提供的标签、数量和商品名称，不生成分组利润或占比。

移动端将三个区域纵向堆叠为可展开账本。图表可横向滚动，日期控件维持触控尺寸。展开状态使用测量高度和透明度过渡。

### 设置

保持只读状态页：当前账号、账号权限、飞书连接、版本。使用四行账本式列表和一个克制警告区，不新增开关、个人资料、集成或主题设置。

### 登录

使用单一紧凑登录面板，位于页面视觉中心略上方。只包含 X 标记、产品名、说明、账号、密码、错误消息和登录按钮。不得添加注册、忘记密码、状态缩略图或版权文字。

### 抽屉和弹窗

桌面交易抽屉宽 460px 左右，固定标题与操作区，中间表单可滚动。移动端为近全屏底部表单，表单以单列为主，日期可在可读时并排，底部操作区考虑安全区与软键盘。

确认弹窗宽 400px 左右，标题、说明和两个操作按钮。取消按钮获得初始焦点；危险色仅用于删除操作。

## 动效

- 页面内容首次进入：180–260ms，8px 位移和透明度，模块错峰 30–40ms
- 侧栏选中指示：180ms ease-out
- 按钮/输入/行悬停与焦点：120–160ms
- 图表柱：从基线增长 420–560ms，按数据点短错峰
- 数字：只在首次载入时轻量递增，不在每次重渲染重复播放
- 抽屉：桌面从右侧 240ms；移动端从底部 260ms；遮罩 180ms
- 确认弹窗：遮罩淡入，弹窗 0.98 比例与 8px 上移复位
- 可展开列表：高度、透明度和箭头旋转 180–220ms
- 保存、删除、导出、筛选更新必须提供清晰的进行中与完成反馈

所有动画使用 `prefers-reduced-motion` 降级为无位移、极短或无动画。动画不得阻塞点击、滚动、表单输入或测试。

## 组件与代码边界

- `AppShell`：桌面侧栏、顶栏、移动底栏、主题和账号操作
- 通用基础组件：按钮、图标按钮、页面标题、状态标签、提示条、面板标题、空/错/加载状态
- 交易功能：工具栏、桌面表格、移动列表、分页、批量操作条、交易抽屉
- 数据展示：经营摘要、月度利润图、利润分析图、可展开统计列表
- 样式：以 CSS 自定义属性承载主题、字号、间距、圆角、阴影与动效，不新增重量级 UI 框架

现有 API、React Query 数据流、路由、导出和 CRUD 行为保持不变。

## 错误、空状态与可访问性

- 加载状态使用小型旋转指示与稳定最小高度，避免巨大空白卡片
- 错误状态提供错误消息和重试按钮
- 空状态提供简短说明和当前已有的创建/重置路径，不新增业务动作
- 所有交互元素保留可见键盘焦点；抽屉和弹窗维持焦点管理与 Escape 行为
- 颜色不是唯一状态信号；状态仍有文字
- 移动触控目标至少 44×44px，正文不低于 14px
- 文本和关键控件满足 WCAG AA 对比度

## 验证标准

1. 原有测试继续通过，并补充布局/状态组件的必要行为测试。
2. `typecheck`、`lint`、`test`、`build` 全部通过。
3. 在桌面原生概念比例附近和 390×844 移动视口逐页验证。
4. 验证浅色、深色、减少动画三种设置。
5. 核心流程：登录、搜索筛选、排序分页、选择与批量操作、新增/编辑/删除、导出、分析下钻、主题切换。
6. 使用浏览器截图与概念图逐项对照：结构、文案、排版、颜色、圆角、边框、图表、移动重排、抽屉和弹窗。
