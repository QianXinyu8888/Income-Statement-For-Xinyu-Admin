# 自用中工作区设计

日期：2026-08-27  
状态：已确认，待实施计划

## 目标

新增一个独立的“自用中”工作区，用于集中管理正在自用、以及已经准备出售的物品。用户可以在此快速把物品标记为“在售中”，或通过一个轻量的售出确认窗口补全售价、售出日期和备注后标记为“已售出”。

这不是另一套交易数据：它复用现有的飞书交易记录和状态字段，售出后仍由“交易明细”统一承接历史记录、利润与分析。

## 范围

### 包含

- 新增独立路由 `/self-use`，在桌面侧边栏和移动端底部导航中显示“自用中”。
- 工作区只列出状态为“自用中”或“在售中”的交易；“已售出”和“已退货”不出现在这里。
- macOS 风格的桌面优先界面：浅灰背景、白色圆角内容区、细边框、紧凑工具栏、柔和状态色。
- 表格默认显示：商品名称、成本、持有天数、状态、操作。
- 商品名称可打开现有完整交易编辑面板。
- 按商品名称搜索；按“全部 / 自用中 / 在售中”分段筛选；按购入日期、持有天数或成本排序。
- 每行显示互斥的“在售中”和“已售出”操作。
- “已售出”弹出确认小窗口，包含售价、售出日期、备注和利润。
- 加载、空状态、错误重试、保存失败保留输入、成功反馈与数据刷新。
- 中文和英文导航、可访问性文案与键盘操作。

### 不包含

- 出售平台、商品链接、挂牌价、图片管理、销售看板或最近已处理区域。
- 新的飞书字段、数据库、后端数据模型或利润公式。
- 批量处理、撤销操作或独立的“自用开始日期”。

## 页面与交互

### 自用中工作区

页面标题为“自用中”，副标题展示当前符合范围的物品数量。工具栏包含搜索、状态分段筛选、排序和新增入口。空状态明确说明当前没有自用或在售物品，并提供新增交易入口。

表格使用平衡密度：

| 列 | 内容 | 行为 |
| --- | --- | --- |
| 商品名称 | 交易标题 | 点击打开现有交易编辑面板 |
| 成本 | 飞书返回的总成本，缺失时显示 `—` | 只读 |
| 持有天数 | 飞书公式字段，缺失时显示 `—` | 只读 |
| 状态 | 自用中或在售中 | 只读状态文字与柔和状态色 |
| 操作 | “在售中”“已售出”互斥选项 | 见下文 |

操作区采用 macOS 风格的紧凑复选控件：细描边方框、选中时系统绿和对勾，标签分别为“在售中”“已售出”。只有当前状态为“在售中”时第一个选项呈选中状态；“已售出”不是持久选中状态，而是进入售出确认流程的入口。

### 标记为在售中

用户选择“在售中”后，立即将该交易状态更新为“在售中”。成功后刷新本工作区和其他交易相关缓存，状态列及控件立刻反映新状态；失败时保留原始状态并显示错误提示。

将已处于“在售中”的物品切回“自用中”不属于第一版范围；用户如需回退，可通过现有完整编辑面板修改状态。

### 标记为已售出

用户选择“已售出”后，不立即更改记录，而是打开 macOS 风格的确认小窗口：

- 标题：`确认售出`
- 上下文文案：`今天是你自用 {商品名称} 的第 {持有天数} 天`
- 售价：必填，金额格式
- 售出日期：必填，默认当天，允许修改
- 备注：可留空；界面不显示“可选”或示例占位文案
- 利润：根据售价与现有总成本即时显示；总成本或售价缺失时显示 `—`
- 操作：取消、确认售出

确认时，客户端保留记录中未显示的字段，只更新状态、售价、售出日期和备注。确认成功后关闭窗口、刷新交易和经营摘要缓存、显示“已售出”反馈，并从工作区列表中移除该记录。失败时窗口继续打开，用户已输入的数据保持不变并显示错误。

## 数据与技术边界

- 复用 `Transaction`、`TransactionInput`、`TRANSACTION_STATUSES` 和现有飞书字段映射。
- 列表请求使用现有 `GET /api/v1/transactions`，按状态查询后在页面内合并“自用中”和“在售中”两类记录；搜索与排序沿用现有查询能力。
- 标记“在售中”使用现有 `POST /api/v1/transactions/batch-status`，以单个记录 ID 提交；该接口只改状态，不会覆盖其他字段。
- 确认售出使用现有 `PUT /api/v1/transactions/:id`，提交由原记录构成、并覆盖状态、售价、售出日期与备注后的完整 `TransactionInput`。
- 利润、总成本和持有天数仍由飞书公式计算。保存成功后重新拉取数据，以飞书返回结果为准。
- 不新增后端端点、环境变量或飞书字段。

## 组件边界

| 单元 | 职责 | 依赖 |
| --- | --- | --- |
| `SelfUsePage` | 路由页面、查询参数、筛选/排序状态、缓存失效、反馈 | React Query、API 客户端、导航 |
| `SelfUseList` | 响应式表格和行渲染 | `Transaction`、状态展示 |
| `SelfUseRowActions` | 在售中和已售出入口、单行操作状态 | 单行 mutation 回调 |
| `SaleConfirmDialog` | 售价/日期/备注表单、利润预览、焦点管理和校验 | `Transaction`、交易 schema |
| `AppShell` | 新导航入口 | i18n、路由 |

组件不直接读写飞书；页面集中发起 mutation，子组件通过清晰的回调上报操作。

## 视觉与响应式

- 沿用应用主题变量与现有深色模式，不引入平台专属字体依赖；macOS 风格通过圆角、间距、分段控件、细描边和低饱和色实现。
- 桌面端以表格为主；手机端使用现有交易列表的等价列表模式，保留商品、成本、持有天数、状态和两个操作入口。
- 售出确认窗口在窄屏占用安全的最大宽度，支持滚动；不添加装饰性的假窗口控制按钮，以避免它们被误认为真实关闭控件。
- 复选控件和按钮必须具有明确的 `aria-label`、键盘焦点和禁用状态。

## 错误处理

- 列表加载失败：显示既有错误状态和重试按钮。
- “在售中”更新失败：不乐观移除或改变状态；显示接口返回的错误信息。
- 售出表单校验失败：在表单内显示首个错误，且不发送请求。
- 售出保存失败：保留表单、输入和对话框焦点，显示错误信息。
- 保存进行中：禁用会产生重复提交的控件；关闭窗口和取消操作保持一致且安全。

## 测试策略

### 域与请求

- 覆盖自用工作区的状态范围、搜索和排序查询构造。
- 覆盖“在售中”单项状态更新请求。
- 覆盖确认售出时完整输入的合并：保留成本、运费、购入日期等未编辑字段。

### 组件

- 只渲染“自用中”和“在售中”记录，已售出记录不显示。
- 状态分段筛选、搜索、排序和空状态。
- 点击“在售中”后调用状态更新；失败时维持原 UI。
- 点击“已售出”打开对话框；售价和日期为必填。
- 利润根据价格和总成本显示，数据不完整时显示 `—`。
- 售出成功后关闭对话框、刷新缓存、从列表移除；失败时保留输入和错误提示。
- 对话框的 Escape、Tab 焦点循环、可访问名称和移动端布局。

## 验收标准

1. 导航中可以进入独立“自用中”页面。
2. 页面仅管理自用中和在售中物品，已售出记录不会停留在列表。
3. 用户能直接标记“在售中”。
4. 用户必须填写售价和售出日期才能确认“已售出”。
5. 售出确认窗口中的文案、字段和“利润”标签与确认的原型一致。
6. 售出成功后的数据与交易明细、经营摘要一致，且由飞书公式结果最终决定。
7. 页面在加载失败、保存失败、空数据、桌面端和手机端均保持可用。
