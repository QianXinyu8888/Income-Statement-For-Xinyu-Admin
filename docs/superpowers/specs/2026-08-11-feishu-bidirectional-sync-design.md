# 飞书双向数据同步设计

## 目标

以飞书多维表格为唯一交易数据源，使 Web 端和飞书端的数据最终保持一致：

- Web 端的新增、编辑、删除和批量操作直接写入飞书，飞书确认成功后 Web 才提示成功。
- 飞书端的数据变更在 Web 页面保持打开时自动刷新，不需要用户手动刷新浏览器。
- 交易列表、概览和分析数据使用同一刷新策略，避免不同页面显示不一致的旧数据。
- 修复 Cloudflare Pages 生产部署，使新版 `/api/v1/*` Pages Functions 真正在线运行。

本次不追求秒级推送，不引入 Webhook、KV、Durable Object 或 WebSocket。

## 架构与数据源

飞书多维表格继续是唯一持久化数据源。Web 端不建立本地交易数据库或第二份业务数据副本。

```text
Web 用户操作
    → /api/v1/transactions
    → Cloudflare Pages Function
    → 飞书 Bitable API
    → 飞书确认写入
    → Web 作废查询缓存并重新读取

飞书用户操作
    → 飞书表格成为最新值
    → Web 自动刷新
    → /api/v1/transactions 或 /api/v1/analytics/summary
    → 重新读取飞书
    → 更新页面
```

飞书公式字段继续只读。Web 只写入商品名称、状态、日期、成本、运费、成交价、备注和排序；总成本、利润、ROI 和持有天数始终以飞书计算结果为准。

## 自动刷新策略

React Query 的全局查询策略调整为：

- 交易、概览和分析查询在页面可见时每 15 秒重新请求。
- 页面不可见时不继续轮询，避免无意义的飞书 API 流量。
- 浏览器窗口重新获得焦点时立即刷新。
- 网络从断开恢复时立即刷新。
- Web 端写入成功后不等待下一轮询，立即作废交易和分析查询并重新读取。

15 秒是默认平衡值：页面可以自动看到飞书变更，当前约 165 条记录的规模也不需要引入额外基础设施。

## 写入与冲突规则

- 新增、编辑和删除等待飞书 API 成功响应后才关闭抽屉或显示成功通知。
- 批量操作继续返回逐条结果；部分失败时保留选择，并在重新读取后显示飞书中的真实状态。
- 同一条记录在两端同时编辑时采用最后一次成功保存生效。本次不增加字段级合并或冲突对话框。
- 读取和后台刷新失败时保留上一次成功数据，不把页面替换为空列表。

## 同步状态与错误处理

交易页页头增加轻量同步状态：

- 成功读取后显示最近同步时间。
- 后台刷新中不遮挡用户当前操作。
- 后台刷新失败时显示“同步失败”和重试入口，同时保留现有列表。
- 首次加载失败继续使用现有整页错误状态。
- 写入失败时保留表单内容或批量选择，并显示飞书返回的可理解错误。

## Cloudflare 生产部署

生产部署必须同时包含 `dist/` 和 `functions/`，不得只上传静态资源。部署目标继续使用 `income-statement-dashboard` Pages 项目和 `20041115.xyz` 自定义域名。

上线验收时：

- `/api/v1/auth/session` 在未登录时返回 JSON `401`，不再返回 SPA HTML。
- `/api/v1/transactions` 在未登录时返回 JSON `401`。
- 登录后的健康检查和交易查询能读取真实飞书数据。
- Web 新版只调用 `/api/v1/*`；旧 `/api/feishu/*` 不再作为产品数据链路的判定依据。

## 测试与验收

### 自动化测试

- API 客户端测试覆盖新增、更新、单删、批量改状态和批量删除的路径、HTTP 方法和请求体。
- Pages Function 测试使用可控的飞书 `fetch` 替身，覆盖读取、新增、更新、删除、部分批量失败和上游错误。
- React Query 测试覆盖可见页面自动刷新、窗口恢复焦点、网络恢复和隐藏页面暂停轮询。
- 交易页测试覆盖最近同步时间、背景失败保留旧数据和手动重试。
- 现有字段映射、排序、分析、导出和鉴权测试全部保持通过。

### 真实飞书端到端验证

使用唯一名称创建一条临时测试记录，并在 `finally` 清理流程中删除：

1. Web API 新增记录，然后通过飞书 API 查询到该记录。
2. Web API 修改记录，然后通过飞书 API 读取到修改后的值。
3. Web API 删除记录，然后确认飞书中该记录已不存在。
4. 直接在飞书修改一条明确的测试记录，确认保持打开的 Web 页面无需手动刷新即显示新值。

端到端脚本不使用现有业务记录作为写入目标。清理失败时必须报告测试记录 ID 和名称，便于人工恢复。

## 成功标准

- Web 端的所有交易写操作在飞书中可见。
- 飞书端的数据变更会自动出现在保持打开的 Web 页面中。
- 交易、概览和分析页最终显示同一份飞书数据。
- 背景同步失败不会丢失已显示数据，用户可以看到错误并重试。
- 生产域名的新版 API 返回正确 JSON 和 HTTP 状态码。
- 自动化质量检查、生产构建和真实飞书端到端流程全部通过。
