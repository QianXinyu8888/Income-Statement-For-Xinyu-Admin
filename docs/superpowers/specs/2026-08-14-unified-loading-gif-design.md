# 统一加载 GIF 设计

## 目标

项目中所有独立加载画面统一展示用户提供的 `icons8-加载.gif`，同时保留现有中文加载文案和无障碍状态语义。

## 范围

- 覆盖统一 `LoadingState` 的所有使用场景：登录状态校验、页面懒加载、概览数据、分析数据、月度趋势和交易列表。
- 不改变登录、保存、删除、健康检查等按钮或行内操作反馈；这些位置不是独立加载画面，继续使用文字可以避免按钮布局抖动。
- 不修改错误状态、空状态或业务请求流程。

## 方案比较

1. **推荐：统一组件引用公共 GIF 资源。** 将 GIF 放入 `public/`，由 `LoadingState` 使用根路径引用。一次修改覆盖所有独立加载画面，资源 URL 稳定，也不会把二进制编码进 JavaScript。
2. 在每个页面分别导入 GIF。可逐页定制尺寸，但会重复实现，容易遗漏后续新增页面。
3. 用 CSS 背景图替换现有 spinner。改动较小，但图片缺少有意义的替代文本，测试和无障碍表达较弱。

采用方案 1。

## 组件与样式

- 新资源：`public/loading.gif`，内容与用户提供的 GIF 完全一致。
- `LoadingState` 保持 `role="status"` 和可见的 `label` 文案，将 CSS spinner 替换为 `img`。
- 图片使用固定样式类 `loading-gif`，按 GIF 原始比例显示，不裁剪、不着色。
- 删除不再使用的 spinner 边框和旋转关键帧。

## 测试与验证

- 新增组件测试，确认默认文案、自定义文案、GIF URL 和替代文本。
- 先运行测试观察缺少 GIF 的失败，再实现并确认通过。
- 运行完整测试、类型检查、lint、构建，并全项目检索确认独立加载画面都通过 `LoadingState`。

## 发布

验证后提交到当前分支，并按用户授权推送到已配置的 GitHub `origin`。
