# 分析卡片订单下钻设计

## 目标

让用户从“利润分析”页的聚合数字快速确认对应产品，并能从产品名称精确跳转到“交易明细”中的唯一订单。定位完成后仅用 1 秒高亮帮助用户找到目标，不自动打开编辑抽屉。

## 范围

- “利润区间”的高收益、稳健盈利、平价回血和亏损分组支持展开产品索引。
- “状态分布”的每个状态分组支持展开产品索引。
- “退货摘要”的退货笔数支持展开产品索引。
- 月度趋势图不提供订单下钻。
- 分析页日期范围继续约束摘要及其产品索引，保证计数与展开内容一致。

## 交互设计

每个可下钻的统计行使用可访问按钮。点击带有订单的统计行后，在该行下方展开仅包含产品名称的精简索引；再次点击同一统计行则收起。计数为零时不允许展开。

展开索引不展示完整订单字段。每个产品名称是一个链接，链接携带唯一订单 ID。点击产品名称后跳转到“交易明细”，由交易页按 ID 精确定位，避免同名产品误匹配。

交易页加载目标所在分页后，将桌面端表格行或移动端订单卡片滚动到可视区域，并执行 1 秒柔和高亮。定位不会勾选订单、不会打开编辑抽屉，也不会覆盖用户可见的交易数据。定位完成后从地址中移除一次性定位参数，刷新页面不会重复高亮。

如果订单在跳转前已被删除或无法访问，交易页保持正常列表状态，不滚动、不高亮，并静默移除无效定位参数。

## 数据与接口

分析摘要为各分组返回精简产品索引。索引项只包含定位和显示所需字段：

```ts
interface AnalyticsOrderIndexItem {
  id: string;
  title: string | null;
}
```

利润区间和状态分布的每个分组增加 `items`；退货摘要增加 `returnItems`。分组计数仍由同一批记录计算，并满足 `count === items.length`。空标题在界面显示为“未命名交易”。

交易列表接口增加精确定位参数 `focusId`。服务端在既有排序及筛选口径下计算目标订单所在页并返回该页；响应携带实际页码。若找不到目标，则按普通第一页请求处理。分析页生成 `/transactions?focus=<encoded-id>` 链接，交易页只在首次解析该参数时把它传给接口。

## 组件边界

- `summarizeTransactions` 负责构造分组计数和产品索引，确保二者来自同一数据源。
- `AnalyticsPage` 负责统计行的展开状态、可访问属性和产品链接。
- `TransactionsPage` 负责解析一次性定位参数、请求目标所在页、滚动、高亮及清理地址。
- `TransactionList` 只负责把目标 ID 映射成桌面行和移动卡片的 DOM 标记及高亮样式，不负责路由和数据请求。

## 可访问性与样式

- 展开按钮使用 `aria-expanded` 和关联区域 ID。
- 产品链接可通过键盘访问，并保留清晰的焦点样式。
- 高亮使用背景色与短暂描边变化，不依赖颜色表达唯一信息；在 `prefers-reduced-motion` 下取消动画过渡，但仍显示 1 秒静态高亮。
- 产品索引过长时在卡片内部限制高度并滚动，避免破坏分析页网格。

## 测试

- 领域测试验证利润区间、状态、退货的索引归属，以及计数与索引长度一致。
- 分析页组件测试验证展开、收起、零计数禁用、空标题回退和唯一 ID 链接。
- API 测试验证 `focusId` 能返回目标所在分页，并验证不存在的 ID 安全降级。
- 交易页/列表测试验证滚动目标、桌面与移动端高亮标记、1 秒后清理，以及不打开编辑抽屉。
- 回归运行单元测试、类型检查、lint 和生产构建。

## 非目标

- 不在分析页展示完整订单字段或编辑订单。
- 不为月度图表增加点击下钻。
- 不支持同时定位或高亮多笔订单。
- 不改变订单现有排序、筛选、选择和编辑行为。
