# 设置页实时角色同步设计

## 目标

设置页的“账号权限”以飞书多维表格“系统用户”表中当前账号记录的“角色”字段为唯一展示依据。每次进入或刷新设置页时重新读取飞书数据，不使用登录令牌中可能过期的角色值。同时删除设置页底部的安全提示。

## 数据流

1. `/api/v1/auth/session` 先验证现有 Session，并取得当前用户名。
2. 接口读取飞书“系统用户”表，通过“用户名”定位当前账号。
3. 接口解析该记录的“角色”字段并返回最新 `user.role`；角色缺失时返回“用户”。
4. 设置页的 session 查询设置为每次挂载都重新请求，绕过全局 30 秒新鲜度缓存。
5. 请求成功后复用 `['session']` 查询缓存，因此设置页和侧栏会显示同一个最新角色。

## 异常处理

- Session 无效时保持现有 401 行为。
- 飞书查询失败、当前用户名在“系统用户”表中不存在或账号已禁用时，会话刷新失败；设置页不把令牌中的旧角色显示为实时结果。
- “角色”字段缺失或为空时统一使用“用户”。

## 界面变更

- 保留“当前账号”“账号权限”“飞书连接”“版本”四项。
- 删除设置页底部“安全提示”区块。
- 不新增轮询、刷新按钮或其他账号管理控件。

## 测试

- API 测试覆盖：Session 用户按用户名回查飞书并返回最新角色、缺失角色的默认值、用户不存在或禁用时失败。
- 设置页测试覆盖：session 查询在页面挂载时强制刷新，展示最新角色，且不再渲染安全提示。
